# T480 N24HT37W temperatures

Tested on a coreboot ThinkPad T480 with EC N24HT37W and Linux 7.2.7.
The driver requires both that firmware ID and T480 DMI identity. Load the
existing `thinkpad_ec_hwmon` module without `experimental=1`; it registers `t480_ec`.
The NixOS option remains `hardware.thinkpadEc.enable`.

Only temperatures are exposed on T480. X230 charger scaling, battery current,
and optional debug cell reads have not been established for this firmware and
are not exposed. Desktop rotation is separate; use
[thinkpad-rotate](https://github.com/p4block/thinkpad-rotate) for T480 motion input.
Both modules serialize EC transactions with `\_SB.PCI0.LPCB.EC.ECLK`.

## Board evidence

Reference: LCFC Windu-2 / NM-B501 WD-2 Logic, revision 0.1, 2017-11-09,
104 sheets. [Schematic and boardview download page](https://www.alisaler.com/lenovo-thinkpad-t480-nm-b501-schematic-boardview/).
Sheet 56 explicitly assigns diode locations; the accompanying TVW confirms
these component references on the bottom side. Boardview device substitutions
and schematic revision differences mean these identify circuit locations,
not a verified bill of materials for every manufactured T480.

| Diode | Component | Schematic location | EC page 0x60 slot |
| --- | --- | --- | --- |
| 1 | Q142 | CPU DC/DC | 2 |
| 2 | Q145 | WWAN | 10 |
| 3 | Q146 | WLAN | 13 |
| 4 | Q198 | Fan | 8 |
| 5 | Q261 | dGPU DC/DC | 12 |
| 6 | Q144 | DIMM | 9 |

A location near a power circuit is an area temperature, not the silicon
junction temperature. These labels have not undergone controlled local-heating
validation. The dGPU-area diode can report a temperature on a UMA board.

Sheet 62 shows U148 on the EC's I2C_CLK_GSENSE/I2C_DATA_GSENSE bus,
with BMA255 and KX022-1020 population options. This does not establish which
part is physically populated on the tested laptop.

## Firmware trace

[Lenovo N24UR39W update](https://download.lenovo.com/pccbbs/mobiles/n24ur39w.iso),
`FLASH/N24ET77W/$0AN2400.FL2`, after removing the 32-byte `_EC` header:
286720 bytes, N24HT37W at offset 0x240, SHA256
`befcb425b9f2a83b959c0ef3ee490420b7c5e5ffa2a792fda821d0ff355e77cf`.
Addresses refer to this ARC600 little-endian payload.

- EC reads A0..AF dispatch through 0x19344 and 0x16284 using selector EC81.
  Page 0x60 reaches 0x1672c, which calls getter 0x259ec. The getter reads
  signed temperatures from six-byte records at 0x803334, checking validity.
  The host wrapper translates unavailable (-1) to 0x80.
- Two 14-entry source tables at 0x30358 and 0x30374 are referenced by
  descriptors at 0x30390/0x30398, then 0x303a0. They differ only at slot 3.
  Each entry holds source index followed by type/flags.
- Acquisition dispatch at 0x261f8 reads these pairs. Types 1/2 call thermal
  getter 0x13acc; type 3 calls 0x21e8c, type 5 calls 0x22274 (battery
  temperature caches, decikelvin converted to Celsius), type 8 calls
  0x2103c. Results enter the exported cache through 0x25eac.
- Slots 0/1/2 are CPU, thermal source 0, and diode 1. Slots 4..7 are two
  temperature sources for each battery. Slots 8/9/10/12/13 select diodes
  4/6/2/5/3. Slots 3 and 11 retain generic names until their source semantics
  are traced further. Thermal source 0 is also labeled generically.

The driver saves EC81, selects 0x60, reads A0..AD, restores EC81 and verifies
restoration while holding ECLK. Cache age at the EC is unknown; Linux caches
for ten seconds. Channels unavailable at module load are hidden. Reload the module to discover
a newly attached battery. A visible channel that later loses data returns
ENODATA, not zero.

## Validation on 2026-09-27

Kernel build and five regression tests passed. Tests cover both firmware/model
policies, failed page selection/data reads, restoration and cache commit.
Live temperatures were 29..39 C. Absent battery/source slots initially returned ENODATA; the final version
hides them at registration, leaving ten available channels on this machine.
Twenty-four concurrent temperature/ACPI battery batches over twelve seconds
passed while the accelerometer delivered 24 fresh frames. Two unload/reload
cycles passed, with no page-restoration errors and accelerometer last_error=0.
Stock BIOS, other EC versions and suspend/resume remain untested.
